# Круг — первая версия

Соцсеть на GitHub Pages + Supabase. Файлы статические, вся логика и данные — в Supabase.

## Состав

| Файл | Назначение |
|---|---|
| `index.html` | Разметка всех экранов |
| `styles.css` | Оформление |
| `app.js` | Логика: посты, вложения, пространства, чаты, модерация |
| `config.js` | Адрес проекта и публичный ключ Supabase |
| `supabase-schema.sql` | Таблицы, правила доступа, функции. Вставляется в Supabase один раз |

## Что уже работает

- Вход через Google, свободная регистрация
- Профиль: имя, логин, описание, настройка «кто может мне писать»
- Посты с фотографиями и файлами (до 100 МБ, видео запрещено)
- Комментарии и лайки, отключение комментариев у поста
- Каналы и сообщества, открытые и закрытые (закрытые — только с галочкой верификации)
- Заявки на вступление и ссылки-приглашения (одноразовые и многоразовые)
- Роли: владелец, админ, участник; исключение и блокировка навсегда
- Личные чаты и чат поддержки (обращения видят владелец и совладельцы)
- Жалобы, предупреждения, мут на 30 дней и вечный мут
- Панель модерации: разбор жалоб, снятие предупреждений, верификация, совладельцы

## Установка

### 1. База данных
1. Зайдите на supabase.com → ваш проект → **SQL Editor** → **New query**.
2. Вставьте весь файл `supabase-schema.sql` → **Run**.
3. Там же выполните, заменив почту на свою:
   ```sql
   update public.profiles set is_owner = true, is_verified = true
    where id = (select id from auth.users where email = 'ВАШ_EMAIL@gmail.com');
   ```
   Это можно сделать только после первого входа через Google.

### 2. Вход через Google
1. Supabase → **Authentication → Providers → Google** → включить, скопировать **Callback URL**.
2. console.cloud.google.com → создать проект → **OAuth consent screen** (тип External).
3. **Credentials → Create credentials → OAuth client ID → Web application**.
4. В **Authorized redirect URIs** вставить Callback URL из шага 1.
5. Client ID и Client Secret вставить в Supabase в окне Google → Save.

### 3. Адрес сайта для перенаправления
Supabase → **Authentication → URL Configuration**:
- **Site URL**: адрес вашего сайта на GitHub Pages
- **Redirect URLs**: добавьте тот же адрес

Без этого вход через Google выдаст ошибку перенаправления.

### 4. Публикация на GitHub Pages
```bash
git init
git add index.html styles.css app.js config.js supabase-schema.sql README.md
git commit -m "Круг: первая версия"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/круг.git
git push -u origin main
```
Затем в репозитории: **Settings → Pages → Source: Deploy from a branch → Branch: main → / (root) → Save**.
Через 1–2 минуты сайт будет по адресу `https://ВАШ_ЛОГИН.github.io/круг/`.

### 5. Хранилище файлов
Бакет `attachments` создаётся самим SQL-скриптом. Если хотите убедиться: **Storage → attachments** — он должен быть там, тип **Private**.

## Важные ограничения

- **Секретный ключ `service_role` не должен попадать в файлы сайта.** В коде нужен только публичный ключ.
- **На бесплатном тарифе Supabase максимальный размер файла — 50 МБ**, хотя лимит в правилах стоит 100 МБ. Для настоящих 100 МБ нужен платный тариф (Pro) либо другой, более мелкий лимит.
- **Одиночный HTML-файл, открытый как `file://`, не заработает** — вход через Google требует настоящего адреса. Для проверки на компьютере запустите `python3 -m http.server` в папке проекта и откройте `http://localhost:8000/`.
- **Назначение совладельцев, удаление пространств и снятие предупреждений** выполняются не в браузере напрямую, а через функции в базе. Подделать их из консоли нельзя.
